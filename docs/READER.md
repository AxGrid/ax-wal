# Читатель ax-wal

Как настроить читателя: все параметры, откуда он начинает, как подтверждает прочитанное, как ведёт себя при сбоях. В конце — удалённый читатель, читатель из архива и флаги командной строки.

## Минимальный пример

```go
r, err := axwal.OpenReader(axwal.ReaderOptions{
    Dir:  "/var/wal",
    Name: "billing-worker-1",
})
if err != nil { … }
defer r.Close()

for {
    payload, idx, err := r.Next(ctx)
    if err != nil {
        return err // ctx отменён либо ошибка чтения
    }
    process(payload)
    _ = r.Ack(idx) // «обработано до idx включительно»
}
```

`Next` только отдаёт запись. Позиция сохраняется, когда вы вызываете `Ack`. После перезапуска читатель с тем же именем продолжит с записи, следующей за последним `Ack`. Гарантия доставки — «не менее одного раза»: записи, отданные, но не подтверждённые до падения, придут повторно.

Читатель рассчитан на одну горутину: `Next`, `NextBatch` и `Ack` нельзя вызывать параллельно. Нужно несколько потоков чтения — откройте несколько читателей с разными именами.

## Параметры `ReaderOptions`

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `Dir` | обязателен | Каталог WAL. |
| `Name` | обязателен | Имя курсора. Уникально среди одновременно работающих читателей; второй с тем же именем не откроется. Без `/` и `\`. |
| `StartFrom` | `StartEarliest` | Откуда начать, если курсора с таким именем ещё нет. См. ниже. |
| `StartAtIndex` | — | Номер записи для `StartFrom: StartAt`. |
| `HeartbeatInterval` | 5 с | Как часто обновляется отметка «читатель жив» в файле курсора. |
| `AckBatchInterval` | 0 | 0 — каждый `Ack` сразу делает fsync курсора. Больше нуля — `Ack` только запоминает номер, а на диск он сбрасывается раз в этот интервал. |
| `PollInterval` | 100 мс | Как часто читатель сам проверяет каталог, если уведомление от файловой системы не пришло. |
| `UseMmap` | false | Отображать закрытые несжатые сегменты в память. Ускоряет холодное чтение больших объёмов. |
| `SkipCorruptSegments` | false | Что делать с повреждённым закрытым сегментом: false — возвращать ошибку, true — пропустить остаток сегмента и идти дальше. |
| `Encryption` | nil | Ключи для зашифрованного WAL: текущий в `Key`, прежние в `OldKeys`. |
| `Logger` | `slog.Default()` | Куда писать события читателя. |

### Откуда начинает читатель

`StartFrom` действует только при первом запуске с данным именем. Если курсор уже есть, читатель продолжает с него, а `StartFrom` игнорируется.

| Значение | Поведение |
|---|---|
| `StartEarliest` | С самой старой записи, которая есть на диске. |
| `StartLatest` | Пропустить всё, что уже записано; читать только новое. |
| `StartAt` | С записи `StartAtIndex`. Если её уже нет — с ближайшей существующей. |

Если сохранённая позиция указывает на записи, которых больше нет, читатель при открытии переходит на первую существующую и пишет предупреждение.

Чтобы начать заново, удалите файл `<Dir>/cursors/<Name>.cursor` при остановленном читателе или возьмите новое имя.

### Подтверждения: `AckBatchInterval`

| Значение | Цена `Ack` | Сколько записей придёт повторно после падения читателя |
|---|---|---|
| 0 | fsync на каждый вызов | ни одной после последнего успешного `Ack` |
| 10 мс | обновление числа в памяти | до 10 мс потока |
| 100 мс | обновление числа в памяти | до 100 мс потока |

При нуле скорость чтения ограничена диском: один fsync на запись. Если подтверждать каждую запись незачем, либо поставьте интервал, либо вызывайте `Ack` реже — раз в пачку. При штатном `Close` последний `Ack` сбрасывается на диск в любом режиме.

`Ack` принимает только неубывающие номера.

### Связь с очисткой на писателе

Файл курсора — это то, по чему писатель решает, какие сегменты ещё нужны.

- Писатель не удаляет сегменты с записями, которые живой читатель ещё не подтвердил.
- «Живой» — значит отметка в курсоре свежее `Retention.StaleReaderTTL` писателя (по умолчанию 60 с). Отметку обновляет фоновая горутина читателя, поэтому читатель, который долго обрабатывает одну запись или ждёт в `Next`, остаётся живым.
- `HeartbeatInterval` должен быть заметно меньше `StaleReaderTTL`: не больше половины.
- После `Close` или падения читатель перестаёт обновлять отметку. Через `StaleReaderTTL` писатель перестаёт его учитывать и может удалить непрочитанное. Чтобы читатель мог пролежать дольше, поднимите `StaleReaderTTL` на писателе.
- Эту защиту обходят `Writer.TruncatePrefix` и `Retention.MaxRetainAge`: они удаляют независимо от курсоров.

## Методы

| Метод | Назначение |
|---|---|
| `Next(ctx)` | Следующая запись и её номер. Блокируется, пока записи нет. |
| `NextBatch(ctx, max)` | До `max` записей: ждёт первую, остальные берёт без ожидания, сколько уже есть. |
| `Ack(idx)` | Подтвердить обработку до `idx` включительно. |
| `CurrentIndex()` | Последний подтверждённый номер. |
| `NextIndex()` | Номер записи, которую вернёт следующий `Next`. |
| `HeadIndex()` | Номер последней записи в WAL. Читает хвост открытого сегмента — не вызывайте в плотном цикле. |
| `Lag()` | Отставание от конца лога: записей и байт. |
| `Stats()` | Счётчики, см. ниже. Безопасно вызывать из другой горутины. |
| `Close()` | Освободить ресурсы. Курсор остаётся на диске. |

`NextBatch` при ошибке в середине возвращает уже прочитанные записи без ошибки; ошибку вернёт следующий вызов.

## Поведение при изменениях в логе

Читатель не отдаёт запись под чужим номером и не останавливается молча. `Next` либо отдаёт запись, либо ждёт, потому что лог действительно кончился, либо перепрыгивает реальную дыру и сообщает об этом, либо возвращает ошибку.

| Ситуация | Что делает читатель |
|---|---|
| Конец лога; писатель молчит, закрыт или ещё не запущен | Ждёт, пока появится запись или отменят `ctx`. |
| Сегмент отротировался, сжался или выгружен в архив во время чтения | Ничего не замечает. |
| Сегмент удалён позади курсора (retention после выгрузки в архив) | Ничего не замечает: удаляется только подтверждённое. |
| Нужные записи исчезли: `TruncatePrefix`, `MaxRetainAge`, сегмент удалён руками, лог начинается позже позиции читателя | Если дыра держится 1 с, переходит на первую существующую запись, пишет предупреждение с пропущенным диапазоном, увеличивает `SkippedRecords`. |
| Читатель отсутствовал и вернулся | Продолжает после последнего `Ack`; если этого места нет — с первой существующей записи. |
| Писатель упал посреди записи, в хвосте открытого сегмента мусор | Ждёт. Перезапущенный писатель отрезает хвост, читатель продолжает со следующей настоящей записи. |
| Писатель потерял хвост и оказался позади читателя | Ждёт, пока лог снова дойдёт до его позиции; одно предупреждение в лог. |
| Закрытый сегмент повреждён: не сходится CRC, файл короче, чем обещает имя, не распаковывается | По умолчанию — ошибка на каждом вызове. С `SkipCorruptSegments` — запись в лог, остаток сегмента пропускается, чтение продолжается со следующего. |
| Открытый сегмент повреждён, а писатель пишет дальше | Ошибка `ErrCorruptRecord` на каждом вызове. После ротации сегмент станет закрытым и сработает правило выше. |

Пауза в 1 с перед прыжком нужна, чтобы не принять за дыру мгновение, когда писатель переименовывает сегмент.

Перепрыгивание — это потеря записей для данного читателя. Если это недопустимо, следите за `SkippedRecords`.

## Ошибки

| Ошибка | Когда | Что делать |
|---|---|---|
| `context.Canceled`, `context.DeadlineExceeded` | Отменён `ctx` | Штатное завершение. |
| `ErrCorruptRecord` | Запись не прошла проверку CRC | Сегмент повреждён. Восстановить из архива или реплики либо включить `SkipCorruptSegments`. |
| `ErrTruncatedRecord` | Закрытый сегмент обрывается раньше времени | То же. |
| `ErrEncryption` | Нет ключа, ключ не тот или запись изменена | Проверить `Encryption`. Запись при этом считается прочитанной: следующий `Next` вернёт следующую. |
| ошибка из `Ack` | Номер меньше уже подтверждённого | Ошибка в вызывающем коде. |

Проверять через `errors.Is`.

## Счётчики `Stats()`

| Поле | Смысл |
|---|---|
| `Name` | Имя курсора. |
| `NextIndex` | Номер следующей записи. |
| `AckedIndex` | Последний подтверждённый номер. |
| `NextCalls`, `AckCalls` | Число отданных записей и подтверждений. |
| `SkippedRecords` | Сколько записей пропущено из-за дыр и повреждённых сегментов. |
| `ErrCorruptSegs` | Сколько раз встречен повреждённый сегмент. |
| `SegmentSwitches` | Сколько раз открывался сегмент. |
| `WaitWakeups` | Сколько раз читатель уходил ждать новых данных. |

Для оповещений: `SkippedRecords > 0`, рост `ErrCorruptSegs`, отставание из `Lag()`.

## Шифрование

```go
Encryption: &axwal.EncryptionConfig{
    Key:     currentKey,           // 32 байта
    OldKeys: [][]byte{previousKey}, // ключи до смены
}
```

Нужный ключ подбирается для каждой записи сам. Какой ключ нужен сегменту, видно по `key_fingerprint` в файле `wal-F-L.meta` и в манифесте архива; сравнивать с `axwal.KeyFingerprint(key)`.

## Удалённый читатель

Читает WAL другого сервера через `axwal-serve`. Интерфейс тот же: `Next`, `NextBatch`, `Ack`, `Close`.

```go
rr, err := axwal.DialRemoteReader(ctx, axwal.RemoteReaderOptions{
    Addr: "127.0.0.1:9001",
    Name: "analytics",
    SSHTunnel: &axwal.SSHTunnelConfig{
        Host: "primary.example.com:22", User: "root",
        KeyFile: "/root/.ssh/id_ed25519", KnownHostsFile: "/root/.ssh/known_hosts",
    },
})
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `Addr` | обязателен | Адрес `axwal-serve`. С туннелем — как его видит удалённый сервер. |
| `SSHTunnel` | nil | Идти через SSH. Поля: `Host`, `User`, `KeyFile`, `KeyPassphrase`, `Agent`, `KnownHostsFile`, `DialTimeout`. |
| `TransportKey` | nil | Общий ключ, 32 байта: взаимная проверка и шифрование прямого TCP-соединения. Должен совпадать с ключом сервера. См. `REPLICATION.md`. |
| `Name` | обязателен | Имя курсора на стороне источника. |
| `StartIndex` | 0 | С какой записи начать при первом подключении. 0 — с самой старой. |
| `BatchSize` | 256 | Сколько записей сервер кладёт в одну пачку. |
| `AckEvery` | `BatchSize` | Отправлять подтверждение серверу раз в столько записей. |
| `DialTimeout` | 15 с | Предел на подключение целиком: TCP, SSH, приветствие. |
| `IdleTimeout` | 60 с | Если от сервера нет ни данных, ни пингов дольше этого, соединение считается мёртвым и закрывается. |
| `QueueDepth` | `BatchSize × 4` | Сколько записей держать в памяти между сетью и вызывающим кодом. |
| `Logger` | `slog.Default()` | Журнал. |

Удалённый читатель сам не переподключается: при обрыве `Next` возвращает ошибку, и вызывающий код подключается заново. Позицию помнит сервер по `Name`. Автоматическое переподключение есть у реплики (`RunReplica`), см. `REPLICATION.md`.

## Читатель из архива

Читает записи прямо из B2 / S3 / каталога, без доступа к серверу с WAL.

```go
ar, err := axwal.OpenArchiveReader(ctx, axwal.ArchiveReaderOptions{
    Store:    store,
    Prefix:   "wal/kiosk-prod",
    FromTime: time.Date(2026, 9, 1, 0, 0, 0, 0, time.UTC),
    ToTime:   time.Date(2026, 9, 30, 23, 59, 59, 0, time.UTC),
})
for {
    payload, idx, err := ar.Next(ctx)
    if err == io.EOF { break }
    …
}
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `Store`, `Prefix` | обязательны | Где лежит архив. |
| `FromIndex`, `ToIndex` | 0 — без границы | Диапазон номеров, включительно. |
| `FromTime`, `ToTime` | без границы | Диапазон дат. Работает по сегментам целиком: в записях нет меток времени. |
| `Encryption` | nil | Ключи, как у обычного читателя. |
| `TempDir` | системный | Куда скачивать сегменты, по одному. |
| `Follow` | false | В конце архива не возвращать `io.EOF`, а ждать новых сегментов. |
| `PollInterval` | 30 с | Как часто проверять архив в режиме `Follow`. |
| `GapTimeout` | 10 мин | В режиме `Follow`: сколько ждать недостающий сегмент, прежде чем считать его дырой. Сегменты выгружаются параллельно и могут приходить не по порядку. |
| `SkipMissing` | false | Что делать с дырой: false — вернуть `ErrArchiveGap`, true — перепрыгнуть и посчитать в `Stats().SkippedRecords`. |
| `ArchiveEncryption` | nil | Ключ шифрованного архива, см. `ARCHIVE_ENCRYPTION.md`. |
| `Logger` | `slog.Default()` | Журнал. |

Курсоров в архиве нет: `Ack` ничего не делает, позицию хранит вызывающий код.

### Дыры в архиве

Читатель архива не пропускает записи молча. Если запрошенных записей в архиве нет, а более поздние есть, `Next` возвращает `ErrArchiveGap` с точным диапазоном и продолжает возвращать её при повторных вызовах. Так сделано, чтобы пересчёт или поиск по всей очереди не дал результат с незаметно выпавшим куском.

| Ситуация | Что считается дырой |
|---|---|
| Сегмента нет в манифесте, а следующие есть | Диапазон между соседними сегментами. |
| Сегмент есть в манифесте, а объекта в хранилище нет | Диапазон этого сегмента. |
| Архив объявлен начинающимся с записи N, а первый сегмент в манифесте начинается позже | Диапазон от N до первого сегмента. Начало архива писатель записывает в манифест до первой выгрузки. |
| Запрошен `FromIndex`, которого в архиве нет | Диапазон от `FromIndex` до первой существующей записи. |
| Диапазон `FromIndex..ToIndex` заканчивается внутри дыры | Тоже дыра, а не «чистый конец». |
| Шифрованный архив без манифеста, объекта нет, а «голова» архива говорит, что лог идёт дальше | Дыра. Перепрыгнуть её нельзя даже с `SkipMissing`: без манифеста неизвестно, с какой записи начинается следующий сегмент. |

С `SkipMissing: true` читатель перепрыгивает дыру, пишет предупреждение с диапазоном и увеличивает `Stats().SkippedRecords`.

Проверить архив заранее и довыгрузить пропавшее можно командой `axwal-cli archive -check`, см. ниже.

## Командная строка

Следить за логом:

```bash
axwal-cli tail -dir /var/wal [-name dbg] [-from earliest|latest|<номер>] [-hex] [-key-file key.bin]
```

Выгрузить диапазон:

```bash
axwal-cli dump -dir /var/wal [-from N] [-to M] [-follow] [-raw | -jsonl] \
    [-key-file key.bin] [-old-key-files a.bin,b.bin]
```

| Флаг | Значение |
|---|---|
| `-from`, `-to` | Диапазон номеров включительно. Без `-to` — до последней существующей записи. |
| `-follow` | Не останавливаться в конце, ждать новых записей. |
| `-raw` | Содержимое записей как есть, по одной на строку. |
| `-jsonl` | `{"idx":N,"payload":{…}}` — содержимое вставлено как JSON. |
| без `-raw` и `-jsonl` | `{"idx","len","payload"}` с base64; этот формат принимает `restore`. |
| `-store`, `-since`, `-until` | Читать из архива, а не из каталога; отбор по датам. |

Проверка архива:

```bash
axwal-cli archive -store <адрес> [-archive-key-file k] -check [-deep] [-dir /var/wal] [-repair]
```

| Флаг | Значение |
|---|---|
| `-check` | Проверить: нет ли дыр в нумерации, на месте ли каждый объект. Код возврата 1, если что-то не так. |
| `-deep` | Скачать каждый объект и проверить полностью: размер, контрольную сумму, расшифровку, CRC записей и их количество. |
| `-dir` | Каталог WAL писателя. Дополнительно сверяет: всё, что на диске помечено `.archived`, действительно лежит в архиве. Работает и для архива без манифеста. |
| `-repair` | Вместе с `-dir`: снять отметку `.archived` с локальных сегментов, которых в архиве нет или которые там повреждены. Писатель выгрузит их заново. |

Все читатели, их положение и скорость:

```bash
axwal-cli readers -dir /var/wal [-interval 1s] [-watch] [-stale-ttl 60s] [-json]
```

```
log: /var/wal   records 1..23961   5 segment(s), 367.6KB   writing 825/s

READER              ACKED      LAG    SPEED CATCH-UP        HEARTBEAT STATE     PID
billing-worker      23942       19    824/s keeping up         1s ago alive   26937
catching-up         17007     6954   3500/s in 3s              0s ago alive   26937
old-migration        1500    22461      0/s not running        5s ago stale   26937
slow-exporter        1443    22518    297/s falling behind     1s ago alive   26937
```

| Колонка | Смысл |
|---|---|
| `ACKED` | Последняя подтверждённая запись. |
| `LAG` | Сколько записей до конца лога. |
| `SPEED` | Записей в секунду, измерено за `-interval`. В первой строке — скорость писателя. |
| `CATCH-UP` | `caught up` — отставания нет; `keeping up` — отстаёт меньше чем на две секунды своей работы; `in 3s` — догонит через столько при текущих скоростях; `falling behind` — читает не быстрее, чем пишут; `not moving` — жив, но не подтверждает; `not running` — читатель не работает. |
| `HEARTBEAT`, `STATE` | Когда читатель последний раз подал признак жизни. `stale` — дольше `-stale-ttl`; такой читатель больше не удерживает очистку на писателе. |

| Флаг | Значение |
|---|---|
| `-interval` | Сколько наблюдать, чтобы измерить скорость. 0 — только положения, без скорости. |
| `-watch` | Обновлять таблицу каждые `-interval` до Ctrl-C. |
| `-stale-ttl` | С какого возраста отметки считать читателя неработающим. Ставьте равным `Retention.StaleReaderTTL` писателя. |
| `-json` | Один JSON-объект на снимок, для мониторинга. |

Положение берётся из файла курсора, то есть это последний `Ack`. Отсюда два следствия: читатель с `AckBatchInterval` виден с опозданием на этот интервал, а читатель, который вообще не вызывает `Ack`, стоит на месте, сколько бы он ни прочитал. Команда ничего не регистрирует и не блокирует; на мастере в списке видны и реплики — под именем из `-name`.

Те же данные из кода: `axwal.ListCursors(dir)` и `axwal.InspectLog(dir)`.

Только положения, без измерения, и сводка по каталогу:

```bash
axwal-cli cursors -dir /var/wal
axwal-cli stats   -dir /var/wal
```

`tail` и `dump` регистрируют временный курсор с именем вида `axwal-cli-dump-<pid>`. Пока команда работает, он, как любой читатель, удерживает очистку на писателе.
