# Шифрованный архив в публичном бакете

Архиватор может выгружать сегменты зашифрованными и под именами, по которым нельзя понять, что внутри. Такой бакет можно сделать публичным: без ключа в нём лежат бессмысленные блобы, а с ключом лог читается потоком с самого начала по обычному HTTPS, без учётных данных хранилища.

## Включение на писателе

```go
archiveKey := loadKey() // 32 байта

w, err := axwal.OpenWriter(axwal.WriterOptions{
    Dir:              "/var/wal",
    CompressOnRotate: true,
    Archive: &axwal.ArchiveConfig{
        Store:      b2store.New(keyID, appKey, bucket),
        Prefix:     "wal/kiosk-prod",
        Encryption: &axwal.ArchiveEncryption{Key: archiveKey},
    },
})
```

Больше ничего не меняется: повторы, подбор хвостов после перезапуска, отметка `.archived`, манифест работают как раньше.

Ключ — 32 случайных байта, например `head -c 32 /dev/urandom > archive.key`. Потеряете ключ — архив не прочитать.

## Что получается в бакете

```
wal/kiosk-prod/73a690d6bbd4fdaf1981144f90a2cabf
wal/kiosk-prod/85fdca7dc52de72bd3fb5b94c8847f90
wal/kiosk-prod/8897af7d8544fb51d9125f00e2dba74b
wal/kiosk-prod/ff51d60b57468c1f9c9d7d0e204ad827
```

Три сегмента и манифест; какой из них манифест, без ключа не определить.

| Скрыто | Видно всем |
|---|---|
| Содержимое записей | Число объектов |
| Номера записей в сегменте и их количество | Размер каждого объекта |
| Порядок сегментов | Время загрузки каждого объекта |
| Время первой и последней записи | Префикс, который вы задали |
| Какой объект — манифест | |

По размерам и времени загрузки можно оценить объём и ритм записи. Если это важно, бакет лучше оставить закрытым.

Параметр `Layout` в этом режиме не действует: дата в пути выдала бы порядок и время, поэтому все объекты лежат прямо под `Prefix`.

## Чтение

### Из кода

```go
import "github.com/axgrid/ax-wal/store/httpstore"

r, err := axwal.OpenArchiveReader(ctx, axwal.ArchiveReaderOptions{
    Store:             httpstore.New("https://f004.backblazeb2.com/file/my-bucket/wal/kiosk-prod", nil),
    ArchiveEncryption: &axwal.ArchiveEncryption{Key: archiveKey},
})
for {
    payload, idx, err := r.Next(ctx)
    if err == io.EOF { break }
    …
}
```

- `httpstore` — хранилище «только чтение»: обычный GET, без ключей доступа. Подойдёт публичный бакет B2 или S3, CDN, любой статический файловый сервер.
- С закрытым бакетом работает то же самое через `b2store` / `s3store`.
- Доступны `FromIndex` / `ToIndex`, `FromTime` / `ToTime` и `Follow` (ждать новые сегменты).
- Читатель потоковый: расшифровывает, распаковывает и разбирает записи по мере скачивания. На диск ничего не пишется.

### Из командной строки

```bash
# что лежит в архиве
axwal-cli archive -store https://f004.backblazeb2.com/file/my-bucket/wal/kiosk-prod \
    -archive-key-file archive.key

# пройти всю очередь с начала
axwal-cli dump -store https://…/wal/kiosk-prod -archive-key-file archive.key -raw

# диапазон по номерам или по датам
axwal-cli dump -store https://… -archive-key-file archive.key -from 100000 -to 200000 -jsonl
axwal-cli dump -store https://… -archive-key-file archive.key -since 2026-09-01 -until 2026-09-30 -raw

# восстановить в локальный WAL / держать локальную копию
axwal-cli restore -store https://… -archive-key-file archive.key -dir /tmp/wal-copy
axwal-mirror      -store https://… -archive-key-file archive.key -dst /srv/wal-copy
```

Формат адресов:

| Адрес | Что это |
|---|---|
| `https://f004.backblazeb2.com/file/<бакет>/<префикс>` | публичный бакет B2 |
| `https://<бакет>.s3.<регион>.amazonaws.com/<префикс>` | S3 с публичным чтением |
| `b2://<бакет>/<префикс>`, `s3://<бакет>/<префикс>` | закрытый бакет, ключи доступа из окружения |

### Как читатель находит объекты без листинга

Публичный бакет не даёт перечислять файлы, и читателю это не нужно.

- **По манифесту.** Имя манифеста вычисляется из ключа. В расшифрованном манифесте — список сегментов с номерами и временем записей, по нему работает отбор по диапазону и датам.
- **По цепочке, если манифеста нет** (`DisableManifest`). Имя сегмента вычисляется из ключа и номера его первой записи. Читатель берёт сегмент, начинающийся с записи 1, дочитывает его, узнаёт номер следующей записи и вычисляет имя следующего сегмента. Так проходится весь лог. Отбор по датам в этом режиме недоступен, и архив должен начинаться с записи 1.

### Неверный ключ

С неверным ключом вычисляются другие имена, и по ним в бакете ничего нет. Читатель в этом случае возвращает ошибку «wrong archive key, wrong prefix, or an empty archive». Отличить неверный ключ от пустого архива нельзя в принципе — это и есть свойство схемы.

Без ключа: `axwal-cli` сообщит, что манифеста нет, а хранилище не перечисляется.

## Два уровня шифрования

| | `WriterOptions.Encryption` | `ArchiveConfig.Encryption` |
|---|---|---|
| Что шифрует | каждую запись | объект в архиве целиком |
| Где действует | локальный диск, реплика, архив | только архив |
| Скрывает номера и количество записей | нет | да |
| Скрывает имена файлов | нет | да |

Они независимы. Для публичного бакета нужен второй. Если включены оба, читателю архива нужны оба ключа: `ArchiveEncryption` и `Encryption`.

## Формат

Для тех, кто хочет читать архив своим инструментом.

Производные ключи, `K` — ключ архива:

```
encKey  = HMAC-SHA256(K, "axwal-archive-enc-v1")
nameKey = HMAC-SHA256(K, "axwal-archive-name-v1")
```

Имена объектов, первые 16 байт HMAC в hex (32 символа):

```
сегмент  = HMAC-SHA256(nameKey, "segment" || uint64_be(номер первой записи))
манифест = HMAC-SHA256(nameKey, "manifest")
```

Тело объекта:

```
[8 байт: "AXWAE" 00 00 01] [16 байт: соль]
затем блоки: AES-256-GCM(открытый текст до 65536 байт) = шифротекст + 16 байт тега

ключ объекта = HMAC-SHA256(encKey, "object" || соль)
nonce блока  = 00 00 00 || uint64_be(номер блока с нуля) || флаг (1 у последнего блока, иначе 0)
```

Флаг последнего блока защищает от обрезания объекта по границе блока. Открытый текст сегмента — файл сегмента как на диске: zstd, если включено сжатие, внутри записи `[длина u32 BE][CRC32C u32 BE][содержимое]`.

Соль вычисляется из содержимого: `HMAC-SHA256(encKey, "salt" || тип || SHA-256 открытого текста)`, первые 16 байт. Поэтому один и тот же файл всегда шифруется в одни и те же байты — повторная попытка выгрузки не создаёт новый объект. Разное содержимое даёт разную соль и разный ключ.

В библиотеке это доступно напрямую:

```go
name, _  := axwal.ArchiveObjectName(key, firstIndex)   // имя объекта
mname, _ := axwal.ArchiveManifestName(key)             // имя манифеста
plain, _ := axwal.NewArchiveDecrypter(key, httpBody)   // поток открытого текста
```

## Ограничения

- **Смены ключа архива нет.** Новый ключ — это новые имена: заведите новый префикс. Старый архив читается старым ключом.
- **Включение на существующем архиве.** Уже выгруженные открытые объекты остаются как есть; шифруются только новые выгрузки, и манифест начинается заново под скрытым именем. Чище начать с нового префикса.
- **Проверено** автотестами: формат, подмена, обрезание и перестановка блоков, выгрузка с повторами, чтение через HTTP-сервер без листинга, проход по цепочке без манифеста. С настоящим публичным бакетом B2 не проверялось.
